# Proposal

## Why

看板在同一块屏幕中切换「变更／规格」时会卸载另一侧列表，导致展开的条目和变更内的任务筛选等状态丢失；切换按钮还会清空搜索，滚动位置也不能可靠恢复。现有插件图标只用于包元数据，右侧栏标签标题没有注册图标，难以从侧栏快速辨识看板。

## What Changes

- 以会话和工作区为边界，分别保留看板「变更／规格」视图的搜索与滚动位置；在顶部视图切换、变更筛选切换及后台数据刷新后，尽量保留仍存在条目的展开状态和变更内「文件／任务」、仅看未完成及分组折叠状态。
- 仅缓存浏览状态，不跨会话沿用；任务写入进行态、错误提示和监听健康状态继续由当前活动会话实时决定，不把旧数据当成当前内容。
- 重新设计可在小尺寸辨识的 OpenSpec 看板图标，统一插件图标与右侧栏视觉意象，并使侧栏标签标题实际显示图标；添加标签页的引导项也使用对应图标。

## Capabilities

### New Capabilities

- `dashboard-view-state`: 看板内部屏幕复用时，按会话与工作区保留独立的视图、列表和条目浏览状态。
- `sidebar-tab-icon`: OpenSpec 看板在右侧栏标签与添加标签页引导中的可辨识图标。

### Modified Capabilities

无；`change-task-visibility` 现有的独立筛选与数据不变约束继续成立，本变更补充它在视图切换后的浏览状态恢复。

## Impact

- 客户端 `src/client/dashboard.ts`、`src/client/rows.ts`、`src/client/entry.ts`、`src/client/styles.ts` 与 `icon.svg`，以及相关前端状态、插槽注册和打包测试；必要时更新 `README.md`。
- 不更改 Host 文件读写、任务复选框写入防护、OpenSpec 文件结构或持久化格式；不新增跨浏览器刷新／设备的持久化要求。
