# Design

## Context

参见 proposal.md。当前 `src/client/model.ts` 在读取模型内截断变更、规格、文件与任务行数，并以固定目录深度停止递归；`src/host/watch.ts` 对监听根、订阅者、路径及深度有限额，超过时通知不可用。`src/client/watch.ts` 已处理传输错误并在服务端发送 `unavailable` 事件，但 `src/client/dashboard.ts` 忽略错误回调。`src/host/task.ts` 的文件大小和任务行号检查会阻止长任务文件的编辑。

## Goals / Non-Goals

**Goals:**
- 取消插件自己的数量及深度阈值，仍使用分批、有限并发和事件合并限制瞬时负载，而不是限制最终可见条目数量。
- 监听失效与恢复状态只占据现有标题行；保持已载入数据可浏览。
- 任务编辑的路径、会话权限、版本、原始行校验不退化。

**Non-Goals:**
- 不修改 DSH 底层目录服务或其返回 `truncated` 时的行为；按用户决定，此罕见情况不新增 UI 提示。
- 不取消沙盒、文件目标限制、会话策略日志校验等安全防护，也不新增定时轮询。

## Decisions

1. **读取数量不封顶，读取工作量分批。** `model.ts` 不再对变更、规格及文件切片，删除固定遍历深度；保留仅用于简介生成的少量候选文件读取优化，因其不会影响条目完整性。任务文本利用 `read(offset, limit)` 的行分页一直读取到 `eof`，按真实返回行数递增偏移；空页、未推进或版本变化时终止并按读取失败处理，避免死循环及拼接不同版本的任务内容。加载变更使用有限并发的工作队列并保留既有排序；替代“一次读全部”的无界并发会淹没文件服务。
2. **取消监听器数量/深度阈值，但维持工作区边界。** `watch.ts` 不再因根、订阅、目录数量和目录深度直接报错，继续共享根监听并用规范路径、非符号链接及已注册目标键防止越界和重复遍历；底层操作系统资源耗尽则发 `unavailable`，交由标题提示。替代轮询可少占监听句柄，但与用户希望的实时更新不同，且增加后台 I/O。
3. **长文件写入不按旧大小和 500 行上限拒绝。** `task.ts` 先完成现有版本/权限/路径与原行匹配，再修改单个复选框；删除旧的行号、文件大小及预期任务行文本长度阈值，保留输入结构与行内容合法性检查（允许与有效任务行匹配的文本）。底层读写错误仍以现有安全错误机制返回；不把文件整体大小当作权限依据。
4. **监听健康独立于看板内容加载。** `watchBoard` 把 `unavailable` 事件和网络错误统一通知 Dashboard，收到 `ready` 清除失效；无 EventSource 时也报告失效。状态按当前 sessionId/cwd 管理，切会话不继承旧提示；即使数据仍可浏览，也明确告知可能不再实时。标题行用可访问的短文本状态、单行非换行与省略处理保证固定纵向高度，宽度不足时优先保持状态可辨识；不添加单独通知行。

## Risks / Trade-offs

- [大量变更和监听目录会增加内存、句柄和加载时间] → 限制瞬时并发而非总量；出错时释放已有监听资源并展示更新失效，测试超旧阈值、订阅清理和慢读取。
- [分页过程中任务文件变化造成任务行与写入版本不一致] → 每页核对版本并丢弃混合结果，下一次变更事件触发重读；原有乐观写入版本检查仍保留。
- [文件服务自身返回 `truncated` 而未提供分页入口] → 按用户决定保持静默；此类情况不能保证内容完全可见，提案只承诺插件不额外截断。
- [窄侧栏文字与提示争抢横向空间] → 标题容器禁止换行且可缩减，状态标签有紧凑样式与可访问名称，测试小宽度下高度不变。

## Migration Plan

仅更新插件前后端与测试，不迁移持久化数据；回滚部署的插件版本即可恢复旧行为。
