# Design

## Context

变更任务由 `src/client/rows.ts` 的 `ChangeRow` 分组渲染；该组件已为每个变更卡片持有展开状态和子视图状态。`src/client/dashboard.ts` 持有实际任务写入、乐观更新和分组折叠状态，服务端只处理单个任务勾选写入。参见 proposal.md 和 specs/change-task-visibility/spec.md。

## Goals / Non-Goals

**Goals:**
- 在变更卡片内部完成筛选，不增加全局筛选状态或网络请求。
- 保留分组折叠行为和按全部任务计算的进度。

**Non-Goals:**
- 不持久化筛选偏好，不变更任务文件的解析或写入逻辑。
- 不改变文件子视图、变更列表的搜索与状态筛选。

## Decisions

1. **筛选状态由每个 `ChangeRow` 实例本地持有，默认 false。** 卡片已经按 `change.directory` 稳定标识，各卡片状态因此天然独立；组件重新挂载后恢复默认值。替代方案是把变更标识映射提升至 `Dashboard`，但此需求不要求跨挂载保留状态，提升状态只会增加同步负担。
2. **在子视图标签同行、任务标签右侧展示带文字的原生复选框。** 仅在任务子视图呈现该控件，并以中英文文案标明用途；即使归档变更的任务不能编辑，也可筛选浏览。替代方案是把控件放进每个分组或全局工具栏，分别不符合“每个变更独立”或增加重复控件。
3. **只在渲染时过滤任务和空分组，原始任务数据不变。** 使用显示值判断任务是否完成，以匹配现有乐观更新；过滤后无分组时展示明确空状态。分组标题、折叠状态和进度使用未筛选的原始分组，完成任务时若筛选开启，任务可从视图中消失。替代方案是预先改写 `change.groups`，但容易误改数量、状态和文件写入参数。

## Risks / Trade-offs

- [任务勾选后的乐观更新可能让行立即消失，失败后又出现] → 维持现有任务反馈与回滚机制；测试待处理与失败路径，确保错误反馈仍可见或可发现。
- [筛选移除所有分组后出现没有内容的任务面板] → 提供区别于“暂无任务”的“没有未完成任务”空状态。
- [过滤造成分组折叠状态意外重置] → 沿用原有以变更目录和分组编号为键的折叠状态，过滤不改写该状态。

## Migration Plan

仅更新前端包及其测试；不迁移数据，也不改变后端接口。回滚前端更改即可恢复原显示方式。
